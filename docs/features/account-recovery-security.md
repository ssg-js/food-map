# Problem
이메일을 수집하지 않는 개인 계정에 아이디 찾기·비밀번호 재설정·비밀번호 변경 경로가 없다.
# Why
소유자가 비밀번호를 잊거나 정기적으로 변경할 수 있어야 한다.
# Options
이메일 복구는 메일 주소 검증·발송 서비스 추가가 필요하다. 현재 개인 계정 구조에 맞춰 고엔트로피 복구 키를 선택했다. 최초 설정 토큰 재사용은 계정 탈취 위험 때문에 제외한다.
# Decision
256비트 난수 복구 키를 현재 비밀번호 재인증 후 발급한다. DB에는 SHA-256 해시만 저장한다. 아이디 확인은 키 소유 확인으로만 허용하고, 비밀번호 재설정 시 키를 일회 소비하고 모든 세션을 폐기한다. 로그인 상태의 비밀번호 변경은 현재 비밀번호를 요구한다. 비밀번호 해시는 기존 Better Auth crypto를 재사용한다.
# Implementation
웹/PWA/Expo의 로그인에서 찾기 화면으로, 개인 화면에서 계정 보안으로 이동. 잘못된 키는 일반화된 오류. 복구 API와 재인증에 DB 기반 시도 제한, 상태 변경은 Origin 또는 인증된 Bearer 검증. 키는 URL·로그·로컬 저장소에 넣지 않는다. 기존 키는 재발급/비밀번호 변경으로 폐기한다.
기존 사용자는 로그인 후 계정 보안에서 키를 발급해야 한다. 복구 키와 비밀번호를 모두 잃은 상태는 이 기능만으로 복구할 수 없고 별도의 서버 소유자 확인이 필요하다. 공개 가입/이메일/OAuth는 추가하지 않는다.
# Result
실제 서버·분리 DB에서 성공·실패·교차 계정·동시 소비·세션 폐기·재설정 중 로그인 경쟁을 검증했다. 제품 32건, Expo 화면 4건, 기존 단위 21건, DB 마이그레이션 통합 1건 통과. 웹/앱 타입·린트, Next 빌드 및 iOS·Android 번들 생성 확인. 기존 로컬 계정과 맛집을 유지하며 추가 테이블만 적용했다.
# Retrospective
이메일과 OAuth 연결을 추가하면 검증된 채널 기반 복구를 별도 도입할 수 있다.

## 사용 방법
- 로그인 화면 → 아이디·비밀번호 찾기 (`/recover`). 복구 키로 아이디 확인 또는 새 비밀번호 설정. 재설정 후 키는 재사용 불가.
- 로그인 후 계정 보안·비밀번호 변경 (`/account/security`). 현재 비밀번호를 입력해 복구 키 발급·재발급 또는 비밀번호 변경.
- 기존 사용자는 먼저 로그인해 복구 키를 발급·별도 보관한다. 최초 설정 토큰은 복구 키로 쓸 수 없다.
- 비밀번호 변경/재설정 후 모든 기기에서 다시 로그인하고 새 복구 키를 발급한다. 키는 재발급 응답에서만 원문을 표시하고 이후 API로 다시 조회하지 않는다.
- 브라우저 클립보드는 복사 버튼을 직접 눌렀을 때만 쓴다. 앱은 선택 가능한 텍스트로 보관한다.
- 외부 API, 메일 서비스, 유료 연결, 공개 회원가입은 추가하지 않았다. 실기기 실행 검증은 이 환경에서 수행하지 않았다.
