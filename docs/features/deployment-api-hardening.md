# Problem
개인 서비스의 API 본문 크기·실패 응답 캐시·인증 시도 기록·다중 검색 한도 예약이 클라우드 배포 조건에 맞게 일관되게 보호되지 않았다.
# Why
공개 인터넷에서는 로컬에서 예상하지 않은 요청 크기·로그인 반복·여러 인스턴스 동시 요청을 처리해야 한다.
# Decision
기존 DB/인증/FSD 구조를 유지한다. 프록시·클라우드가 적용해야 하는 보호와 애플리케이션 내부에서 검증 가능한 보호를 분리한다.
# Implementation
POST/PATCH는 64KiB 실제 바이트·10초 JSON reader로 읽는다. 초과413·정지408·잘못된JSON400은 private/no-store이다. 카탈로그 성공·오류·삭제와 인증 응답에도 캐시 금지를 명시한다. 로그인은 전역100회/15분+실제계정10회/15분이며 기간 prefix를 가진 DB 기록을 제한된 배치로 정리한다. 공유/개인 Places 예산은 같은 transaction으로 커밋하고 차단 시 전체 rollback한다. 음수 카운터는 차단한다. 실제 Google fetch 전에만 예약을 완료하고 이미 전송된 실패를 환불하지 않는다.
# Result
단위·제품·DB 통합 회귀 테스트를 추가했다. 상세 증거·심각도·검증·배포 후속 작업은 docs/audits/2026-11-17-backend-review.md 및 최종 종합 보고서에 기록한다.
# Retrospective
앱의 요청 제한은 edge 방화벽·본문/연결 제한·클라우드 권한·실제 API SKU quotas를 대신하지 않는다. 배포 환경이 정해진 뒤 해당 조건을 실제로 검증해야 한다.
