# Context

Place ID만 저장하는 공용 맛집 등록 기능을 실제 목록/관리 기능으로 확장한다.

# Options

1. Google 응답을 Restaurant에 저장: 목록은 쉽지만 기존 저장 정책에 맞지 않는다.
2. 매번 전체 Google 데이터를 다시 조회: 불필요한 호출이 많다.
3. ID·카테고리는 DB에 두고 현재 페이지/선택 장소의 표시 정보만 조회한다.

# Decision

3을 적용한다. 서버 페이징과 카테고리 필터, 화면 수명 동안의 일시 정보, 취소 가능한 요청을 사용한다. 수정·삭제는 기존 관리자 세션 및 메모리 보관 네이티브 토큰으로 제한하고 optimistic concurrency를 적용한다.

# Consequences

Google 장소 정보 조회에 별도 SKU 호출이 발생한다. 지도 로드는 Places 카운터와 별개다. 개발 한도 해제는 환경변수로 유지하고 운영에 그대로 가져가지 않는다. 데이터베이스에 Google 장소 이름·주소·좌표를 저장하지 않는다. 개인 데이터 소유권은 아직 도입하지 않는다.
