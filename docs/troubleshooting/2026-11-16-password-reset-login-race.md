# Problem
비밀번호 재설정과 이전 비밀번호 로그인 요청이 동시에 진행되면 세션 삭제 뒤 늦은 로그인 응답이 새 세션을 만들 수 있다.
# Cause
비밀번호 검증과 세션 생성은 인증 라이브러리 내부의 여러 DB 작업이며 비밀번호 재설정 트랜잭션과 별개다.
# Solution
로그인 시작 전에 credential 해시를 읽고 인증 완료 후 다시 비교한다. 변경됐으면 발급된 세션을 폐기하고 쿠키/토큰을 전달하지 않는다. 재설정/변경 트랜잭션에서는 비밀번호 갱신과 모든 기존 세션 삭제를 함께 수행한다. 복구 키 재발급과 소비는 동일한 credential 행을 먼저 잠그는 순서로 처리한다.
# Verification
테스트 계정의 동시 이전 비밀번호 로그인 8건과 재설정을 실제 서버로 실행하고 발급됐던 토큰 모두 접근 불가, 새 비밀번호 로그인 성공 확인. 키 동시 소비는 1건만 성공하며 이후 재사용 불가. 데스크톱/모바일 양쪽 통과.
# Lessons Learned
기존 세션 삭제뿐 아니라 진행 중 인증 요청도 고려해야 한다. 실제 계정의 비밀번호는 테스트에 사용하거나 변경하지 않는다.
