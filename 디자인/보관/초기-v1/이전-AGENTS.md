# 프로젝트 대화 규칙

- 구현이나 파일 변경 전에 작업 범위, 결과물, 예상 시간과 주요 변수를 먼저 안내하고 사용자의 진행 승인을 기다린다. 계획을 위한 읽기 전용 확인은 가능하다. 사용자가 제안된 작업을 실행하라고 요청하면 해당 범위의 승인으로 본다. 승인 후 범위 안에서는 구현과 검증까지 진행하며, 큰 범위 변경이나 추가 비용·계정 연결이 필요하면 확인한다.
- 디자인은 `디자인/수정중/{웹,앱}/페이지명/`에 보관하고 사용자가 확정한 것만 `디자인/확정/{웹,앱}/`에 반영한다. 메인 화면 검토 후 공통 컴포넌트를 다른 페이지에 재사용한다.

- 사용자가 `작업 프롬프트`라고 입력하면 `작업 프롬프트.md`를 읽고, 사용자가 복사해서 채울 수 있도록 양식을 한국어 코드 블록으로 보여준다.
- 양식을 요청하는 것만으로 구현을 시작하지 않는다. 사용자가 작성한 작업 내용을 보내며 실행을 요청하면 그 범위에서 작업한다.
- 필수 입력은 `하고 싶은 작업` 하나다. 나머지 항목은 선택이며, 비어 있는 항목을 모두 되묻지 않는다. 진행에 꼭 필요한 정보만 확인하고 일반적인 세부 사항은 합리적으로 결정한다.
- 기타 설정은 사용자가 추가할 수 있도록 선택 항목으로 유지한다. 미입력 항목을 영구적인 프로젝트 설정이나 무제한 작업 허가로 해석하지 않는다.
- 사용자가 양식 수정을 요청하면 `작업 프롬프트.md`를 갱신한다. 여러 차례 수정하며 양식을 발전시킨다.
- 완료 시 변경 내용, 실제로 수행한 검증, 실행 또는 확인 방법, 남은 문제가 있다면 간단히 보고한다.
